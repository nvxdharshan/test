GlassWorm Supply-Chain Malware Compromises 400+ Repositories
Across GitHub, npm, VS Code and OpenVSX

Published: 18 March 2026 Threat Actor: GlassWorm (likely Russian-speaking) Severity: Critical (CVSS 9.8) Campaign Status: Active
1. Threat Overview

GlassWorm is a persistent, evolving supply-chain threat actor that has launched its most extensive campaign to date in March 2026, compromising 433 packages, repositories, and extensions across GitHub, npm, the Visual Studio Code Marketplace, and the OpenVSX Registry in a coordinated multi-platform offensive. Researchers at Aikido Security, Socket, Step Security, and the OpenSourceMalware community collectively identified the campaign, with all evidence pointing to a single threat actor based on shared Solana blockchain C2 infrastructure, identical payload techniques, and consistent operational patterns observed since October 2025.

The defining technical characteristic of GlassWorm is the use of invisible Unicode Private Use Area characters to conceal malicious JavaScript payloads directly within source code. These characters render as zero-width whitespace in every major code editor, terminal, GitHub diff view, and code review interface, making the hidden code completely undetectable through visual inspection. The malware uses the Solana blockchain as a command-and-control channel, polling a wallet address every five seconds for updated payload URLs, a mechanism that cannot be taken down through traditional domain seizure or DNS blocking.

Invisible by Design

No standard code review process, syntax highlighter, diff tool, or linter will detect GlassWorm payloads. A commit that appears completely clean in GitHub's UI, in VS Code, and in every terminal can contain a full malicious payload hidden inside what looks like an empty backtick string. This is not a detection gap that can be closed through staff training alone. Automated Unicode scanning controls are required.

2. Campaign Timeline

March 2025: Aikido Security first discovers malicious npm packages concealing payloads using Private Use Area Unicode characters.

May 2025: Aikido publishes research detailing the risks of invisible Unicode in supply-chain attacks, establishing the technique as an emerging threat class.

October 17, 2025: GlassWorm's first confirmed mass wave. Seven OpenVSX extensions are compromised with approximately 35,800 combined downloads. The malware harvests npm, GitHub, and Git credentials, targets 49 cryptocurrency wallet extensions, deploys SOCKS proxy servers, and installs hidden VNC servers for full remote access. Koi Security documents this as the first self-propagating worm targeting VS Code extension ecosystems.

November 6, 2025: Three additional VS Code extensions are infected on OpenVSX with approximately 10,000 downloads. The attackers push a new Solana transaction to update C2 addresses while the exfiltration server remains unchanged. GlassWorm also expands to GitHub repositories for the first time.

January 2026: A third wave infects four VS Code extensions with over 22,000 combined downloads. Rust-based implants are introduced alongside the invisible Unicode technique, indicating active tooling development.

March 3 to March 9, 2026: The current and largest wave. Approximately 150 GitHub repositories are compromised using the ForceMemo technique, where malicious code is force-pushed while preserving original commit messages, authors, and timestamps, leaving no pull request trail. The campaign simultaneously expands to npm and the VS Code Marketplace.

March 12 to 13, 2026: Socket identifies 72 malicious OpenVSX extensions linked to the campaign. The total confirmed compromised component count reaches 433 across all platforms.

3. Attack Chain
1

Developer Account Compromise: GlassWorm gains initial access by stealing developer credentials from previously infected machines through earlier campaign waves. Compromised credentials allow the attackers to authenticate directly to GitHub, npm, and extension marketplace accounts without triggering authentication anomalies.

2

Malicious Code Injection via Force-Push (ForceMemo): On GitHub, attackers rebase the latest legitimate commits on the default branch, injecting hidden Unicode payloads into source files, then force-push the changes. The original commit message, author name, and author date are preserved. Only the committer date changes, leaving no visible diff, no pull request, and no code review trail in GitHub's interface.

3

Invisible Payload Encoding: Malicious JavaScript is encoded within Unicode Private Use Area characters in the ranges U+FE00 to U+FE0F and U+E0100 to U+E01EF. A hidden decoder extracts bytes from these zero-width characters and passes the result to JavaScript's eval() function. The encoded content is invisible in every editor, terminal, diff viewer, and code review tool.

4

Solana Blockchain C2 Polling: Once executed, the first-stage payload queries a Solana blockchain wallet address every five seconds for a command-and-control URL embedded as a memo in blockchain transactions. Between November 27, 2025, and March 13, 2026, Step Security traced 50 new transactions updating the payload URL. Because Solana is a public blockchain, this C2 channel cannot be seized, blocked by domain takedown, or disrupted through traditional law enforcement mechanisms.

5

Second-Stage Payload Execution: The C2 URL delivers the Node.js runtime and a JavaScript-based information stealer. The stealer collects developer credentials, access tokens, SSH keys, CI/CD secrets, environment variables, and cryptocurrency wallet data from 49 targeted wallet extensions. Stolen data is exfiltrated to attacker-controlled servers.

6

Transitive Dependency Abuse on OpenVSX: On the OpenVSX registry, attackers exploit the extensionPack and extensionDependencies fields to turn initially benign-appearing extensions into transitive delivery vehicles. A trusted extension can be updated to begin pulling a separate GlassWorm-linked extension only after initial trust has been established with users, making the malicious dependency appear to come from a known, previously safe source.

7

LLM-Assisted Camouflage: Aikido Security assesses that attackers are using large language model assistance to generate cover commits that are stylistically consistent with each target project. Surrounding changes include documentation tweaks, version bumps, and bug fixes that appear natural and project-appropriate, making manual code review detection even less likely.

4. Threat Actor Profile

GlassWorm is a persistent, technically sophisticated threat actor with a demonstrated pattern of multi-ecosystem targeting, rapid tooling iteration, and operational longevity. Koi Security, which independently tracks the actor, obtained access to an attacker-controlled server and identified keylogger data indicating a Russian-speaking operator using RedExt C2 infrastructure, multiple cryptocurrency exchanges, and encrypted messaging platforms. Victims identified in the server data include developers and organisations across the United States, Europe, Asia, and Latin America, as well as a government entity in the Middle East.

The actor's operational security discipline is notable. Payload updates are delivered through the Solana blockchain rather than traditional C2 infrastructure, the ForceMemo commit technique preserves original authorship metadata to evade commit history review, and the scale of the March 2026 wave (433 components across four registries in under two weeks) indicates significant automation investment, likely including LLM-assisted commit generation.

The use of the same Solana wallet address for C2 across all campaign waves provides definitive linkage between the October 2025, November 2025, January 2026, and March 2026 activity, confirming a single persistent actor rather than multiple copycat campaigns.

5. Technical Analysis

Unicode Steganography: GlassWorm exploits Unicode Variation Selector characters (U+FE00 to U+FE0F) and Variation Selector Supplement characters (U+E0100 to U+E01EF). These are legitimate Unicode code points that modify the rendering of adjacent characters and have no visible glyph of their own. When used outside their intended context, they render as zero-width invisible characters in every mainstream code environment. A JavaScript backtick string that appears completely empty in any editor can contain a full malicious payload encoded across hundreds of these characters.

Blockchain C2: The Solana blockchain provides the attackers with a censorship-resistant, always-available C2 channel. Instructions are embedded as memos in blockchain transactions to a fixed wallet address. The payload URL is updated by publishing a new transaction, a process that takes seconds and cannot be blocked through conventional security infrastructure. Defenders cannot take down the C2 by reporting the domain, disrupting hosting, or requesting registrar action.

Information Stealer Targets: The second-stage stealer is documented to harvest GitHub personal access tokens, npm authentication tokens, Git credentials from configuration files, SSH private keys from default key locations, environment variables from .env files and shell profiles, CI/CD pipeline secrets including GitHub Actions tokens, cloud provider credentials, and wallet data from 49 specific cryptocurrency browser extensions.

Self-Propagation Risk

Once a developer machine is infected, GlassWorm uses the harvested npm, GitHub, and OpenVSX credentials to infect additional packages and extensions on the victim's behalf. A single infected developer can therefore become an unwitting propagation vector, spreading GlassWorm to every package they publish and every repository they push to. This exponential spread mechanism is why the confirmed victim count grew to 433 components across four registries within a single two-week wave.

8. Detection Guidance

Unicode Character Scanning: Implement automated scanning of all source code repositories for Unicode Private Use Area characters in the ranges U+FE00 to U+FE0F and U+E0100 to U+E01EF. These characters have no legitimate use in source code outside of specific internationalisation contexts. Any occurrence in a JavaScript, TypeScript, or Python file should be treated as a critical finding. Tools including Aikido Security, Socket, and grep-based regex patterns can detect these characters. A sample grep pattern is: grep -rP "[ï¸-ï¸]" ./src.

Commit History Verification: For all GitHub repositories, configure branch protection rules requiring signed commits and prohibiting force-pushes to default branches. Implement CODEOWNERS files and require reviews from code owners for all changes. Retroactively audit commit histories for the period from March 3 to March 9, 2026, comparing committer dates against author dates and flagging any discrepancy, which is the primary ForceMemo signature.

Extension and Package Inventory: Establish an approved extension and package allowlist for developer workstations. Any VS Code extension or npm package installed outside of this approved list should generate an alert. Implement a registry of all installed extensions by machine, enabling rapid scope assessment when new GlassWorm IOCs are published.

Network-Level Detection: Deploy outbound DNS and HTTPS inspection to detect connections to Solana RPC endpoints from developer workstations and CI/CD runners. Solana API calls from these environments are not a normal traffic pattern in most development organisations. A detection rule for repeated requests to api.mainnet-beta.solana.com or equivalent RPC endpoints at regular short intervals (approximately 5 seconds) is a reliable GlassWorm C2 indicator.

Process Monitoring: Deploy endpoint detection rules to alert on the Node.js executable spawning from paths within VS Code extension installation directories, typically ~/.vscode/extensions/ on Linux and macOS, or %USERPROFILE%\.vscode\extensions\ on Windows. Legitimate extensions do not directly spawn Node.js processes outside the VS Code extension host.

9. Mitigation Steps
1

Immediately audit all VS Code extensions, npm packages, and GitHub dependencies installed or updated between March 1 and March 18, 2026. Cross-reference against published GlassWorm IOC lists from Aikido Security, Socket, and Step Security. Remove or roll back any flagged component and treat any machine that ran a flagged extension as potentially compromised pending investigation.

2

Rotate all developer credentials as a precautionary measure for any developer whose workstation may have been exposed during the compromise window. This includes GitHub personal access tokens, npm authentication tokens, SSH private keys, cloud provider access keys, CI/CD pipeline secrets including GitHub Actions tokens and environment variables, and any credentials stored in .env files, shell profiles, or IDE keychain storage.

3

Implement Unicode scanning in your CI/CD pipeline as a mandatory pre-merge gate. No code should be merged into any production or release branch without passing a scan for Private Use Area Unicode characters. This single control directly blocks the primary GlassWorm delivery mechanism and prevents compromised upstream dependencies from introducing hidden payloads into your codebase.

4

Enable branch protection on all GitHub repositories to prohibit force-pushes to default and release branches, require code owner reviews, and mandate commit signing. Force-push protection is the direct countermeasure to the ForceMemo injection technique used in the March 2026 wave. These settings should be enforced at the organisation level via GitHub organisation policies, not left as repository-level configurations that individual developers can modify.

5

Block outbound connections to Solana RPC endpoints from all developer workstations, CI/CD runners, and build servers at the network perimeter. Deploy SIEM detection rules for any internal system making repeated HTTPS requests to Solana API endpoints. This disrupts the GlassWorm C2 heartbeat, preventing payload updates and exfiltration even on machines that have already executed the first-stage loader.

6

For any developer machine where GlassWorm infection is confirmed or suspected, treat the machine as fully compromised: isolate from the network immediately, preserve memory and disk state for forensic analysis, and assume all credentials and secrets accessible from that machine are compromised. Initiate a full incident response process including notification of any downstream package consumers or GitHub repository dependants.

10. Security Best Practices
★
Treat the software supply chain as an attack surface with the same rigour applied to network perimeters. Every third-party package, extension, and dependency is a potential entry point. Implement Software Composition Analysis (SCA) tooling that scans for known-malicious packages and behavioural indicators, not just CVE-listed vulnerabilities, across all dependency ecosystems your teams use.
★
Establish a formal VS Code extension allowlist across the development organisation. Developers should be able to request additions to the allowlist through a defined process, but should not have unilateral authority to install extensions from any source without prior approval. Auto-update of extensions should be disabled in favour of controlled rollouts that pass through your scanning pipeline.
★
Implement dependency pinning and lockfile enforcement in all projects. Rather than pulling the latest version of a package on each install, pin all production and development dependencies to specific verified versions using lockfiles, and validate lockfile integrity in CI/CD. This significantly reduces the window for a compromised package version to reach your builds.
★
Subscribe to security advisories from Aikido Security, Socket, and Step Security, all of whom actively track GlassWorm and publish IOC lists and new wave notifications. The March 2026 wave grew from 151 to 433 confirmed components in under a week. Early subscription to these feeds reduces the time between public disclosure and your own defensive response.
★
Enforce the principle of least privilege for all CI/CD pipeline tokens and GitHub Actions. Pipeline credentials should have write access only to the specific repositories and registries they need, and should expire on a short rotation schedule. A compromised pipeline token with broad write access to your npm organisation or GitHub repositories is a high-value GlassWorm propagation target.
★
For software development organisations specifically: consider implementing a dedicated, clean build environment (ephemeral CI runners with no persistent credentials, fresh workspaces per build, and no developer extensions installed) that is physically and logically separated from developer daily-use machines. Build artefacts produced in this environment carry significantly lower supply-chain compromise risk than those built on developer laptops that run arbitrary VS Code extensions.
